# 美术替换接口（W0 → anime-v3）v0.1

## 已定

- **造型方向锁定：anime-v3**  
  权威图：`docs/03-美术/角色/anime-v3-*.jpg`  
  - `anime-v3-shen-guichi.jpg` → 主角  
  - `anime-v3-lu-qingge.jpg` → 同伴甲（陆清歌）  
  - `anime-v3-ning-xiaoman.jpg` → 同伴乙（宁小满）
- **灰盒阶段**：继续用 `docs/03-美术/W0-占位/`（色块/几何 UI）跑通流水线
- **替换原则**：玩法与配置只认 **逻辑 key**；美术资源通过 Addressables / Resources 地址映射，换皮不改表主键

## 资源 key 约定

| 逻辑 key（配置 / 代码） | 灰盒（W0） | 目标（anime-v3） |
|------------------------|------------|------------------|
| `portrait.CH_PROTAG` | `W0/characters/…` | `Art/Characters/anime-v3/CH_PROTAG`（自 v3 jpg 导入） |
| `portrait.CH_A` | W0 同伴甲 | `…/CH_A` ← `anime-v3-lu-qingge.jpg` |
| `portrait.CH_B` | W0 同伴乙 | `…/CH_B` ← `anime-v3-ning-xiaoman.jpg` |
| `scene.{scene_id}` | `W0/scenes/SC_01_OPEN` 等（与文件主干同名） | 后续场景初稿（仍按同一 `scene_id`） |
| `ui.dialog` / `ui.choice` / `ui.battle_*` | W0/ui | M3 换皮，key 不变 |

导入后 Sprite 命名建议与逻辑 key 一致，避免 Dialog/Battle 写死路径。

## 代码侧接口

```csharp
public interface ArtResolver（Web：按 key 映射 URL / public 路径） {
  // 返回可加载地址；灰盒与 v3 只换 catalog，不换调用方
  string PortraitAddress(string characterId);
  string SceneBgAddress(string sceneId);
  string UiAddress(string uiKey);
}
```

- 灰盒实现：`W0ArtResolver` → 前缀 `Art/W0/`
- M3 实现：`AnimeV3ArtResolver`（或同一 resolver 读 ScriptableObject 映射表）
- Flow / Dialog / Battle **禁止**直接拼文件名；只调 `IArtResolver`
